# Largest Product in a Grid

来源：改编自 Project Euler Problem 11

## 原题意

在一个固定的 $20\times20$ 方阵中，求四个在同一直线（竖直、水平或对角线）相邻的数的乘积的最大值。

原题答案：$70600674$。

## 题目

给定 $T$ 组测试数据，每组数据包含一个 $m \times m$ 的方阵。对于每组数据，
求方阵中任意连续四个数（水平、竖直或对角线方向）乘积的最大值。

## 数据范围

- $1 \le T \le 50$
- $4 \le m \le 20$
- $-100 \le a_{i,j} \le 100$

## 改编思路

### 方向一：参数化方阵大小 + 多组测试数据 ✅ 采用

- 做法：将原题固定的 $20\times20$ 方阵改为可变大小的 $m \times m$ 方阵（$4 \le m \le 20$），
  并支持 $T$ 组测试数据。保持"连续四个数"不变。
- 优点：自然、直接的参数化方式；对算法无本质影响（仍是 $O(m^2)$ 枚举），
  难度保持一致；多组数据使题目更适合 OJ 评测。
- 缺点/风险：$m$ 上界仅为 $20$，算法复杂度提升空间不大（更大的 $m$ 也只是常数倍）。
- 结论：✅ 采用

### 方向二：参数化连续数个数 K ❌ 不采用

- 做法：不仅参数化方阵大小，还将"连续四个数"中的 $4$ 改为可变参数 $K$，
  即求任意连续 $K$ 个数的最大乘积。
- 优点：增加变化维度，算法需支持可变窗口长度。
- 缺点/风险：$K$ 变大后乘法可能溢出（即使 int64 也难保证）；
  且本质上仍是 $O(m^2K)$ 枚举，没有带来新的算法挑战，反而增加了数据生成的复杂度。
- 结论：❌ 不采用——引入溢出风险却无实质性算法收益。

### 方向三：只参数化方阵大小，单组输入 ❌ 不采用

- 做法：只将 $20\times20$ 改为 $m \times m$，单组测试数据。
- 优点：极简，与 001-004 的风格一致。
- 缺点/风险：多组输入是更通用的 OJ 格式，且 005 之后已确立多组输入的惯例。
  单组输入不需要 $T$ 参数，造成输入格式不一致。
- 结论：❌ 不采用——多组输入在同难度下提供更好的评测体验。

### 方向四：允许负数，调整乘积策略 ❌ 不采用

- 做法：因矩阵元素可为负数，"最大乘积"需同时考虑偶数个负数的情形。
  可改编为：求绝对值的最大乘积（或分别处理正负）。
- 优点：增加了一些算法考量（需追踪最小值）。
- 缺点/风险：原题矩阵元素均为非负整数，引入负数改变了问题的本质；
  且"求最大绝对乘积"或"最大乘积（考虑负数）"使题面变复杂。
- 结论：❌ 不采用——原题无非负数限制的改编动机，保持 $-100$ 到 $100$ 的范围
  已在原题基础上做了合理扩展（原题只有 $0$-$99$），不做进一步改动。

## 算法

模拟 + 四方向枚举。对于每个格子 $(i, j)$，检查四个方向（右、下、右下、左下），
每个方向取连续四个数相乘，取最大值。时间复杂度 $O(m^2)$。

注：本题没有比直接枚举更高效的算法（不存在贪心或 DP 优化），因此 brute.cpp
与 std.cpp 实现相同——这是本题的特性而非缺陷。
