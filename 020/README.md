# Factorial Digit Sum

来源：改编自 Project Euler Problem 20

## 原题意

n! = n × (n−1) × ... × 3 × 2 × 1。

例如 10! = 3628800，其各位数字和是 3+6+2+8+8+0+0 = 27。

求 100! 的各位数字和。

## 题目

给定正整数 N，求 N! 的各位数字之和。

## 数据范围

N ≤ 1000。

## 改编思路

### 方向一：参数化 N + 大整数
- 做法：将固定 N=100 改为任意输入 N，N ≤ 1000（或 N ≤ 10^5），需要高精度乘法（或 Python/Java BigInteger）。
- 优点：核心难度从"会写高精度"变为"高效高精度"，N=1000 时 1000! 约 2568 位，N=10^5 时需要用 FFT/NTT 加速多项式乘法。
- 缺点/风险：N=10^5 的 FFT 实现门槛较高，可能不适合入门竞赛；N=1000 的朴素高精度乘法 O(N²) 也可过，区分度不高。
- 结论：✅ 采用（N≤1000 朴素高精度；N≤10^5 用 FFT 加速，分两档）

### 方向二：多组输入
- 做法：T 组测试数据，每组一个 N，求 N! 的数字和。
- 优点：增加题目规模，朴素做法每次重新计算 O(T·N²) 会超时，需要预处理阶乘或递推。
- 缺点/风险：若预处理 1!~1000! 的所有数字和，可以用递推 f(N) = f(N-1) × N 逐步乘，但高精度乘法仍然昂贵。可以用 Python 快速通过。
- 结论：✅ 采用（鼓励预处理/递推优化）

### 方向三：非十进制下的阶乘数字和
- 做法：给定基数 B，求 N! 在 B 进制表示下的各位数字之和。
- 优点：从十进制泛化到任意进制，增加了进制转换的考点。
- 缺点/风险：进制转换 + 高精度混合，代码复杂度上升较多；且"数字和"的概念在非十进制下不太自然（通常只统计十进制）。
- 结论：❌ 不采用（偏离题目自然性）

### 方向四：阶乘的质因子分解
- 做法：求 N! 的质因子分解形式，或求 N! 末尾零的个数（即 Legendre 公式）。
- 优点：经典问题，不需要高精度即可求解；Legend re 公式本身是重要知识点。
- 缺点/风险：这不是"数字和"，与原题方向完全不同；若要结合，可改为"求 N! 去掉末尾零后的最后 K 位数字和"。
- 结论：❌ 不采用（偏离"数字和"主题）

### 方向五：去掉末尾零后的数字和
- 做法：求 N! 去掉所有末尾的零后，剩余数字的各位和。
- 优点：在原题基础上增加一步"去掉末尾零"的处理，需要先计算 N! 中因子 2 和 5 的个数（即末尾零个数），然后对大整数做除法去掉 10 的幂次。
- 缺点/风险：需要高精度除法（除以 10^k），实现更复杂。
- 结论：✅ 采用（有趣且合理的变体，可作为进阶子任务）

### 方向六：逆向问题——给定数字和求最小 N
- 做法：给定数字和 S，求最小的 N 使得 N! 的数字和 = S。若不存在输出 -1。
- 优点：逆向思维，需要分析数字和随 N 的单调性（不严格单调，但大致递增）并二分搜索。
- 缺点/风险：数字和非严格单调（可能出现局部波动），二分不一定正确；验证候选需要高精度计算，复杂度较高。
- 结论：❌ 不采用（单调性不可靠，不适合二分）

### 方向七：输出取模
- 做法：求 N! 的数字和对 M 取模的结果。
- 优点：简单直接，可以套在任何变体上。
- 缺点/风险：纯输出取模没有必要（数字和本身不大，不溢出 64 位），除非 N 超大（此时数字和可能很大但高精度才是瓶颈）。
- 结论：❌ 不采用（意义不大）

## 算法

高精度乘法（数组模拟大整数），依次乘以 1 到 N，最后累加各位数字。

时间复杂度：O(N² · log₁₀(N!)) ≈ O(N² log N)，空间 O(N log N)。
