## 修复流程（每题）

### 步骤 1：确认官方答案
```python
import json
pe = json.load(open("_tools/audit/pe_answers.json"))
official = pe[pid]  # pid 是不带前导零的整数字符串, 如 "439"
```

### 步骤 2：读 std.cpp，找 PE 分支
在源码中搜索 `== "PE"` 或 `== 'PE'`。PE 分支通常形如：
```cpp
if (first == "PE") {
    cout << <某个值或变量> << "\n";
    return 0;
}
```
值可能是：字面量（`12345`、`"abc"`）、变量（`PE_ANSWER`）、表达式。

### 步骤 3：判断 PE 分支值的正确性
- 如果 PE 分支输出 = 官方答案 → 已正确，跳过
- 如果不同 → 需要修复

### 步骤 4：修复方式（按优先级）
1. **如果 PE 分支硬编码了字面值**（如 `cout << 12345LL`）：
   直接替换为官方答案
2. **如果 PE 分支输出变量**（如 `cout << PE_ANSWER`）：
   找到变量的赋值语句，修改赋值
3. **如果 PE 分支有计算逻辑**（不常见）：
   需验证计算是否正确，可能需要修 bug

### 步骤 5：编译 + 运行验证
```bash
g++ -std=c++17 -O2 $pid/code/std.cpp -o /tmp/chk.exe
echo "PE" | /tmp/chk.exe
# 输出应等于官方答案
```

### 步骤 6：同步更新 data/（如有 PE 探针数据点）
如果 data/01.in 是 "PE"，需同步更新 01.out。

## 注意事项

1. **不能盲目正则替换**——上次尝试破坏了 208 个文件的 C++ 语法（已回滚）
2. **变量名各不相同**：PE_ANS、PE_ANSWER、PE_ANSWER_MANTISSA 等
3. **变量可能在参数化分支中也被使用**——修改变量值会影响两个分支
4. **某些题的改编版问题与原题不同**——PE 分支输出改编版答案是设计使然，不应该改成原题答案
5. **每修改一批（20-30 题）就要编译验证**
6. **620 骨架题面已自动填充**（本次会话完成），修改 PE 值时不要动题面
