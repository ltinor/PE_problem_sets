# Power Digit Sum

来源：改编自 Project Euler Problem 16

## 原题意

$2^{15}=32768$，其各位数字之和为 $3+2+7+6+8=26$。求 $2^{1000}$ 的各位数字之和。

原题答案：$1366$。

## 题目

给定 $T$ 组测试数据，每组给出两个整数 $a$ 和 $b$。求 $a^b$ 的各位数字之和。

## 数据范围

- $1 \le T \le 10$
- $2 \le a \le 100$
- $1 \le b \le 1000$

## 改编思路

### 方向一：参数化底数和指数 ✅ 采用

- 做法：将固定的 $2^{1000}$ 改为 $a^b$（$2 \le a \le 100$，$1 \le b \le 1000$）。需要实现大整数乘法（$100^{1000}$ 约 $2000$ 位十进制）。
- 优点：自然的参数化方式，保留了原题的核心挑战（大整数 + 数字和）。扩大了参数范围后，不同 $a$ 会产生不同的数字和分布。
- 结论：✅ 采用

### 方向二：多组输入 ✅ 采用

- 做法：支持 $T$ 组查询，每组给出不同的 $a,b$。
- 结论：✅ 采用

### 方向三：只参数化指数（固定底数 a=2）❌ 不采用

- 做法：只将 $1000$ 改为 $b$，保持底数 $a=2$。
- 缺点/风险：限制太大，题目太窄。$2^b$ 的数字和已在 OEIS 等有已知序列，选手可能直接查表。
- 结论：❌ 不采用——过于受限。

### 方向四：输出整个 $a^b$ 而非数字和 ❌ 不采用

- 做法：要求输出 $a^b$ 的完整十进制表示。
- 缺点/风险：$100^{1000}$ 有 $2000$ 位，输出量巨大，不适合 OJ 格式（输出文件过大）。且原题的趣味正在"数字和"这个小结果。
- 结论：❌ 不采用——输出过大。

### 方向五：多次幂运算合并 ❌ 不采用

- 做法：求 $a_1^{b_1} + a_2^{b_2} + \dots + a_k^{b_k}$ 的数字和。
- 缺点/风险：需要大整数加法+乘法，引入了更多的大数操作但无新算法挑战。
- 结论：❌ 不采用——增加复杂度无实质收益。

### 方向六：考虑高精度浮点近似 ❌ 不采用

- 做法：不精确计算 $a^b$，而是用对数估计数字和。
- 缺点/风险：无法保证准确输出，不适合 OJ 评测。
- 结论：❌ 不采用——无法精确验证。

## 算法

大整数乘法。使用 `vector<int>` 按位存储十进制表示（低位在前），反复乘法计算 $a^b$，然后对所有位求和。每次乘法 $O(L)$，共 $b$ 次乘法，总复杂度 $O(b \cdot L)$，其中 $L$ 是结果的位数（$L \approx b \log_{10} a$）。对于 $b\le 1000$、$a\le 100$，$L\le 2000$，总运算量约 $2\times10^6$，完全可行。
