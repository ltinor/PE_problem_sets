# 自反位置

来源：改编自 Project Euler Problem 305

## 原题意

求 $\sum_{k=1}^{13} f(3^k)$，其中 $f(n)$ 是 $n$ 在 $S$ 中第 $n$ 次出现的起始位置。PE 答案：18174995535140。

## 题目

输入 $K$，求 $\sum_{k=1}^{K} f(3^k)$。

## 数据范围

$1 \le K \le 13$。

## 算法

### 方向一：逐数扫描 + 字符串匹配（核心）

依次生成自然数 $1, 2, 3, \dots$ 的字符串，在拼接过程中匹配目标数字 $m = 3^k$ 的出现。每次找到匹配时计数器加 1，直到达到第 $m$ 次出现。

匹配需考虑两种情形：
- **单个数字内匹配**：目标 $m$ 完全在一个自然数的字符串中出现
- **跨数字边界匹配**：$m$ 跨越两个或多个相邻自然数的拼接边界

对每个 $k$，需扫描到大约 $m \times (\text{数字密度})$ 的范围。最坏情况 $k=13$ 时 $m=3^{13}=1594323$，需扫描到约 $10^{10}$ 量级的位置，直接扫描不可行。

### 方向二：组合计数 + 二分查找（优化）

利用 $S$ 的周期性结构：对每个目标 $m$，统计 $m$ 在不同"数字对齐"下出现的次数。二分查找位置 $P$，计算前 $P$ 个字符中 $m$ 的出现次数，找到第 $m$ 次出现的位置。

需要处理跨数字边界的匹配，按数字长度分段统计。

### 方向三：AC 自动机 + 数位 DP

将问题化为在序列 $1, 2, 3, \dots$ 的字符串拼接中查找模式串。使用自动机或 KMP 进行跨边界匹配，利用数位 DP 快速跳过大量数字。

### 时间复杂度

方向一：$O(M \cdot \text{digit\_length}(M))$，其中 $M \approx 3^{13} \times \text{密度}$，直接扫描不可行于大 $K$。
方向二：二分查找 $O(\log P \times \text{count\_occ})$，需仔细实现跨边界计数。
