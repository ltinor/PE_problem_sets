# Lattice Paths

来源：改编自 Project Euler Problem 15

## 原题意

从一个 $2\times2$ 网格的左上角出发，若只允许向右或向下移动，则恰好有 $6$ 条抵达右下角的路径。对于 $20\times20$ 网格，这样的路径有多少条？

原题答案：$137846528820$。

## 题目

给定 $T$ 组测试数据，每组给出两个整数 $n$ 和 $m$，表示一个 $n \times m$ 的网格。求从左上角 $(0,0)$ 出发，每次只能向右或向下移动，抵达右下角 $(n,m)$ 的不同路径总数。由于答案可能很大，请输出结果对 $10^9+7$ 取模的值。

## 数据范围

- $1 \le T \le 10$
- $1 \le n, m \le 500$

## 改编思路

### 方向一：参数化网格大小 + 取模 ✅ 采用

- 做法：将固定的 $20\times20$ 改为可变的 $n \times m$（$1 \le n,m \le 500$）。由于组合数 $C(n+m,m)$ 增长极快，引入模 $10^9+7$ 取模。使用费马小定理求逆元来高效计算组合数。
- 优点：经典的组合数学问题，取模后适合 OJ 评测；$O(n+m)$ 计算组合数对于 $n,m\le 500$ 非常高效。
- 缺点/风险：取模引入了逆元计算，略增加了算法难度，但这是 OJ 组合计数题的标准做法。
- 结论：✅ 采用

### 方向二：多组输入 ✅ 采用

- 做法：支持 $T$ 组查询，每组给出不同的 $n,m$。
- 优点：允许多个测试用例覆盖不同情形的数据（小网格手工验证，大网格考察复杂度）。
- 结论：✅ 采用

### 方向三：不取模，用大整数输出 ❌ 不采用

- 做法：输出精确的路径数（不用取模），需要大整数。
- 缺点/风险：$C(1000,500)$ 有约 $300$ 位十进制，需要完整大整数实现。虽然可行，但不必要地增加了实现复杂度，对算法本身没有新的考察。
- 结论：❌ 不采用——取模是 OJ 组合计数题的标准做法，避免了无谓的大整数负担。

### 方向四：允许上下左右移动（更复杂的网格路径）❌ 不采用

- 做法：不仅在右下移动，可向任意方向移动，但不能重复访问格子。
- 缺点/风险：完全改变了问题性质（变成哈密顿路径），难度飙升，不符合"不改变难度"原则。
- 结论：❌ 不采用——严重偏离原题。

### 方向五：加入障碍物 ❌ 不采用

- 做法：在网格中设置障碍物格子，求不经过障碍物的路径数。
- 缺点/风险：引入障碍物后需要 DP 或容斥，题目难度从 Level 0 跳升到中档，改变了改编原则。
- 结论：❌ 不采用——改变了难度等级。

### 方向六：矩形网格（n≠m）❌ 不采用

- 做法：原题隐含 $n=m$ 的正方形情形。允许 $n \neq m$ 的矩形网格。
- 备注：实际上方向一已包含此情形（$n,m$ 独立参数），故该方向自动被方向一覆盖。
- 结论：❌ 不采用（已被方向一包含）

## 算法

组合数学。从 $(0,0)$ 到 $(n,m)$ 的路径必须恰好走 $n$ 步向下和 $m$ 步向右，共 $n+m$ 步，其中选择 $m$ 步为向右：
$$\text{ans} = C(n+m, m) \bmod (10^9+7)$$
使用费马小定理求逆元实现组合数取模。时间复杂度 $O(n+m)$ 每组。

## 验证

- brute.cpp 使用 DP（$O(nm)$）在小数据上验证
- 原题答案 $C(40,20)=137846528820$ 可由 std 对 $10^9+7$ 取模后验证（$137846528820 \bmod 10^9+7 = 37846528820$）
