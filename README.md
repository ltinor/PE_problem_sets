# ProjectEuler 题目改编集

本项目将 Project Euler 题目改编为更符合 ACM/OJ 风格的试题：输入参数化、支持多组测试数据，每题包含题面、题解、标准解、暴力解、对拍与正式数据。目前已覆盖第 1 ～ 968 题。项目最初以第 1 ～ 10 题作为示例探讨改编规范（见下文），后按题号顺序批量推进。

## 仓库结构

```
PE_problem_sets/
├── 001/ ~ 968/       每题一个目录（题面 statement.md、题解 NNN.md、改编说明 README.md、
│                     code/ 标准解与暴力解、data/ 测试数据、scripts/ 对拍脚本、Makefile、eval.sh）
├── _template/        最小题目文件结构模板（新题以此为准）
├── _tools/           构建 / 验证 / 测试脚本（含 _tools/verify/ 各批次验证脚本）
├── docs/
│   ├── reports/      分批进度报告与阶段总结（SUMMARY*、RUN_REPORT* 等）
│   └── Skill.md      题目生成流程说明
├── source/           网站源文件（题目页面、文章、资源）
└── _archive/         历史遗留存档（未穷举核对，暂不删除）
    ├── PE_alias/     PE 前缀别名目录（多数为对应数字目录的旧版/残缺副本，
    │                 但含少量独有文件，如 PE0315 的 data/、PE0687 的探索代码）
    ├── shortname_dup/  41/42/43 无前导零重复目录（与 041~043 内容有差异）
    └── misc/         临时脚本、日志、归档包等杂项
```

## 文件说明

`_template/`  中包含了一个最小的题目文件结构，各文件及作用如下：

 ### 1. code 
 - `std.cpp`    
    标准解，用于 `*.out`文件的生成。**保证所有标准解均能正确完成ProjectRuler里的原型试题。**
 - `brute.cpp`
    暴力解，用于标准解的暴力对拍。
 - `gen.cpp`
    小数据生成器，仅用于暴力对拍中。
 - `gen_data.cpp`
    正式数据生成器，以`*.in`格式保存在`data`文件夹内。
### 2. data

存放`*.in` 和`*.out`文件。其中，`*.in`文件由`gen_data.cpp`生成；`*.out`文件由`gen_out.sh`生成。

### 3. scripts
- `check.sh`
    调用，`std.cpp`,`brute.cpp`和`gen.cpp`的暴力对拍脚本。囿于算力限制，只进行了小数据的对拍。
- `gen_out.sh`
    调用`std.cpp`读取`*.in`进行`*.out`的生成。

### 4. Others
- `eval.sh`
  `std.cpp`运行速度检测器。
- `README.md`
  改编说明。包含原题意，新题意和简短的算法说明。
- `statement.md`
  题面。包含题意，样例，输入输出格式。本项目的题面采用较简单直白的叙述，此外对于常用数学概念不作补充说明。

## 改编策略

本项目针对Project Euler的前$10$题进行改编，转化为更符合ACM风格的问题。进行一定程度上拓展的同时不改变试题的整体难度。原Project Euler试题输入通常为固定常数或固定情形，进行改编后改为参数化输入且支持多组测试数据。考虑到这几道试题的算法较为简单（均为level 0），在设计数据时排除了应用逆元，大数算法等内容的情况。

后文简述本文件中各题的改编策略，详细的题意和做法请寻各文件夹内的`README.md`文件：

- 001 ～ 003
  简单数论题，将输入参数化，作为早期改编的试水没有采用多组输入形式。
- 004
  求最大回文数乘积，未作改编。一个可选的改编方案是球第k大回文数，但会引入五位数的情形，是否进行该改编有待考量。
- 005 ～ 008 ， 010
  将输入参数化，采用多组输入形式。
- 009
  将输入参数化，采用多组输入形式，此外作为一个使用spj判题的范例。

## 讨论与后续计划

本文件的主要目的是，探讨下列规范：

1. **文件规范**。当前每题所包含的文件是否合理，是否存在冗余或缺失；题面组织方式是否需要修改。
2. **试题规范**。多文件多组输入是否应作为默认形式；是否需要避免使用 SPJ；是否要考虑数据点的分级。
3. **改编方向**。目前我的改编的大体原则是，**不改变原题难度的前提下，将输入参数化**，是否需要调整？

后续将按题号顺序继续改编 Project Euler 题目。在相关规范（文件结构、改编策略等）明确后，再根据实际工作情况评估时间安排并推进后续内容。
